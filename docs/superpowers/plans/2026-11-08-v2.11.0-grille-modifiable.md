# v2.11.0 — Grille de notation modifiable (étape 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Le professeur définit la grille de notation de l'étape 4 (parties : nom, description, poids, zones, palier, évaluée) ; l'IA note avec cette grille au lieu de `STEP_CRITERIA[4]`.

**Architecture:** Une classe pure `grille` (sans appel Moodle) normalise la grille, fournit la grille par défaut et calcule les parties effectivement notées ; `ai_prompt_builder` l'utilise pour l'étape 4. La grille est stockée en JSON dans `gestionprojet_cdcf_teacher.grille_json`, éditée par un module AMD sur la page du modèle de correction et enregistrée par l'autosave enseignant existant.

**Tech Stack:** Moodle 5.0/5.1, PHP 8.2, AMD (minifié avec `npx --yes terser@5.31.0 src -c -m -o build`), tests PHP purs `php gestionprojet/tests/pure/test_*.php`.

**Spec:** `docs/superpowers/specs/2026-11-08-grille-paliers-cdcf-design.md` (sections 4.1 et 4.2 ; 4.3 à 4.6 sont pour 2.11.1 et 2.11.2).

## Global Constraints

- Version 2.11.0, `$plugin->version = 2026110803`.
- Toute chaîne en `lang/en` et `lang/fr` (le test `test_lang_strings.php` le vérifie) ; commentaires de code en anglais ; en-tête GPL complet.
- Pas de CSS/JS inline : styles dans `styles.css` préfixés `.path-mod-gestionprojet`, JS en AMD.
- Daltonisme : « évaluée / exclue » distingués par un mot et une forme, jamais la teinte seule (bleu positif, orange négatif).
- Ne pas modifier la structure des FS ni `cdcf_helper` (décision du 8 novembre).
- Hors mode paliers, une activité sans grille enregistrée est notée exactement comme aujourd'hui (même texte de grille dans le prompt).
- Fin de développement : déploiement préprod (ZIP sans `tests/pure`) et vérification CLI ; prod seulement sur demande.

## Review Focus

1. `grille_json` vide, invalide ou d'une ancienne forme → la grille par défaut, jamais d'erreur (test Task 1).
2. Toutes les parties exclues → l'évaluation échoue avec un message explicite au lieu d'une note inventée (test Task 3).
3. Poids à 0, négatifs ou texte → ramenés à des entiers ≥ 0 ; somme nulle → poids égaux (test Task 1).
4. Option flexibilité désactivée alors qu'une partie porte sur la zone `flexibilite` → la flexibilité n'apparaît pas dans le prompt (test Task 3).
5. Nom de partie contenant du HTML → affiché comme texte dans l'éditeur et la notation (test statique Task 4).

### Task 1: Classe pure `grille`

**Files:**
- Create: `gestionprojet/classes/grille.php`
- Test: `gestionprojet/tests/pure/test_grille.php`

**Interfaces:**
- Produces (namespace `mod_gestionprojet`, classe `grille`) :
  - `const ZONES = ['interacteurs', 'fonctions', 'criteres', 'niveaux', 'flexibilite', 'contraintes', 'ensemble'];`
  - `const PALIERS = ['', 'F', 'S', 'TS'];` `const EVALUEE = ['auto', 'oui', 'non'];`
  - `public static function default_grid(): array` — les 5 parties actuelles, ids 1 à 5 : Interacteurs 4 `['interacteurs']`, Fonctions de service 6 `['fonctions']`, Critères 4 `['criteres','niveaux','flexibilite']`, Contraintes 3 `['contraintes']`, Cohérence globale 3 `['ensemble']`, noms et descriptions copiés de `ai_prompt_builder::STEP_CRITERIA[4]`, `palier` `''`, `evaluee` `'auto'`.
  - `public static function decode(?string $json): array` — grille normalisée, ou `default_grid()` si vide, invalide ou sans partie.
  - `public static function normalize(array $parts): array` — garde `id` (int), `nom` (string non vide, sinon partie ignorée), `description` (string), `poids` (int ≥ 0), `zones` (sous-ensemble ordonné de `ZONES`, au moins une, sinon `['ensemble']`), `palier` (dans `PALIERS`, sinon `''`), `evaluee` (dans `EVALUEE`, sinon `'auto'`) ; ids en double ou nuls renumérotés.
  - `public static function effective_parts(array $grid, array $lockedzones = []): array` — parties notées : `evaluee === 'oui'`, ou `'auto'` sauf si toutes ses zones sont dans `$lockedzones` (rempli en 2.11.1, vide ici) ; ordre conservé.
  - `public static function scaled_weights(array $parts): array` — `[id => poids sur 20]` (float), chaque poids arrondi à 0,5 près puis l'écart à 20 reporté sur la partie la plus lourde (la première en cas d'égalité), donc somme exactement 20 ; si la somme des poids vaut 0, poids égaux.

  - `decode(null)`, `decode('')`, `decode('{oops')`, `decode('[]')` valent `default_grid()` ;
  - `normalize([['nom' => '', 'poids' => 5]])` vaut `[]` ; `normalize([['nom' => 'A', 'poids' => '-3', 'zones' => ['nope'], 'palier' => 'X', 'evaluee' => 'peut-être']])[0]` a `poids` 0, `zones` `['ensemble']`, `palier` `''`, `evaluee` `'auto'` ;
