# v2.11.1 — Consigne verrouillable élément par élément et champs à compléter (étape 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dans la consigne de l'étape 4, le professeur marque chaque élément « Fourni » (verrouillé) ou « À compléter » (case vide) ; le serveur rétablit les éléments verrouillés à chaque enregistrement élève, l'IA ne note que les champs ouverts, et une partie de grille dont toutes les zones sont fournies est exclue automatiquement.

**Architecture:** Les drapeaux vivent dans le JSON de la consigne (`gestionprojet_cdcf_provided.interacteurs_data`), conservés par `cdcf_helper::normalize`. Une classe pure `consigne_lock` dérive tout de la consigne : copie de départ de l'élève (`seed`), drapeaux pour l'affichage (`with_flags`), rétablissement côté serveur (`enforce`), zones entièrement fournies (`locked_zones`). La copie élève est stockée sans drapeau : les verrous sont toujours relus dans la consigne, le serveur fait foi.

**Tech Stack:** Moodle 5.0/5.1, PHP 8.2, AMD (minifié avec `npx --yes terser@5.31.0 src -c -m -o build`, lancé depuis `gestionprojet/amd`), tests PHP purs `php gestionprojet/tests/pure/test_*.php`.

**Spec:** `docs/superpowers/specs/2026-11-08-grille-paliers-cdcf-design.md` (sections 4.2 et 4.5 ; 4.3, 4.4 et 4.6 sont pour 2.11.2).

## Global Constraints

- Version 2.11.1, `$plugin->version = 2026110804`. Pas de changement de schéma.
- Ne pas changer la structure des FS (FS seules, `interactor2Id = 0` ou deux interacteurs) ni le champ `niveau` (valeur et unité ensemble) : on ajoute seulement des drapeaux booléens.
- Une consigne sans drapeau donne exactement le comportement d'aujourd'hui : même copie de départ, même enregistrement, même prompt.
- Toute chaîne en `lang/en` et `lang/fr` ; commentaires en anglais ; en-tête GPL complet ; pas de CSS/JS inline ; styles préfixés `.path-mod-gestionprojet`.
- Daltonisme : « Fourni » = cadenas + mot ; « À compléter » = bordure en tirets + mot. Jamais la teinte seule.
- DOM construit par `textContent` / `createElement` (pas d'`innerHTML`).
- Fin de développement : préprod (ZIP sans `tests/pure`) + vérification CLI et navigateur ; prod seulement sur demande.

## Choix du concepteur (à signaler à Emmanuel)

1. Drapeaux écrits seulement quand ils sont vrais : `locked`, `gap` sur interacteur, FS et contrainte ; `locked`, `gap`, `niveauLocked`, `niveauGap` sur critère (la description du critère et son niveau se règlent séparément, car SAT et TS se les partagent). La flexibilité suit le niveau.
2. `locked` l'emporte sur `gap` (exclusifs).
3. FS verrouillée = énoncé + interacteurs ; on peut toujours lui ajouter des critères. Contrainte verrouillée = énoncé + justification + FS liée ; contrainte à compléter = énoncé et justification vides.
4. Un élément verrouillé protège son parent : une FS qui contient un critère verrouillé ne peut pas être supprimée ; un interacteur utilisé par une FS verrouillée est rétabli s'il manque.
5. Le texte saisi par le professeur dans un champ « À compléter » devient l'indication grisée de la case vide chez l'élève (« À compléter — en kg »).
6. Les verrous sont relus en direct dans la consigne. Si le professeur verrouille un élément après le début du travail et que l'élève y avait écrit un autre texte, l'élève garde son texte dans un élément à part (nouvel id) et l'élément verrouillé de la consigne est ajouté à côté : aucun texte d'élève n'est perdu (revue finale).
7. La détection « aucune modification » compare la copie à la copie de départ (`seed`), pas à la consigne brute.
8. La soumission n'envoie pas de contenu : le contrôle se fait sur les deux points d'enregistrement (autosave AJAX et web service), ce qui couvre « à chaque autosave et soumission » de la conception.

## Review Focus

1. Requête autosave forgée qui supprime une FS verrouillée ou modifie un critère verrouillé → élément rétabli tel que dans la consigne (test Task 1).
2. Consigne sans drapeau → `enforce` rend la copie de l'élève inchangée (test Task 1).
3. Ids en double dans une requête forgée (deux FS d'id 2 dont une verrouillée) → l'élément verrouillé est rétabli une fois, l'autre reçoit un nouvel id (test Task 1).
4. Champ « À compléter » laissé tel quel → la copie n'est pas jugée « identique à la consigne » à tort, et une copie de départ intacte est bien détectée (test Task 2).
5. Indication de case contenant du HTML → affichée comme texte (test statique Task 4).

### Task 1: Drapeaux dans `cdcf_helper` et classe pure `consigne_lock`

**Files:**
- Modify: `gestionprojet/classes/cdcf_helper.php` (`normalize`)
- Create: `gestionprojet/classes/consigne_lock.php`
- Test: `gestionprojet/tests/pure/test_consigne_lock.php`

**Interfaces:**
- Produces : `cdcf_helper::normalize` conserve `locked` / `gap` (interacteur, FS, contrainte) et `locked` / `gap` / `niveauLocked` / `niveauGap` (critère), seulement quand vrais (`locked` gagne sur `gap`, `niveauLocked` sur `niveauGap`).
- Produces (namespace `mod_gestionprojet`, classe `consigne_lock`, toutes méthodes `public static`, tableaux = structures normalisées de `cdcf_helper`) :
  - `strip_flags(array $data): array` — retire `locked`, `gap`, `niveauLocked`, `niveauGap`, `hint`, `niveauHint`.
  - `has_locks(array $provided): bool` — au moins un `locked` ou `niveauLocked`.
  - `seed(array $provided): array` — copie de départ : sans drapeau, champs « à compléter » vidés (interacteur `name` ; FS `description` ; critère `description` si `gap`, `niveau` et `flexibilite` si `niveauGap` ; contrainte `description` et `justification`).
  - `with_flags(array $student, array $provided): array` — copie de l'élève + drapeaux des éléments de même id dans la consigne (critères appariés par id de FS + id de critère) ; pour un champ « à compléter », `hint` / `niveauHint` = texte de la consigne.
  - `enforce(array $student, array $provided): array` — si `!has_locks($provided)` : `strip_flags($student)`. Sinon, sur la copie de l'élève : ids en double renumérotés (max + 1, la première occurrence garde l'id) ; champs verrouillés repris de la consigne ; éléments verrouillés manquants (et parents qu'ils protègent, choix 4) réinsérés à leur rang dans la consigne (borné à la longueur) ; résultat sans drapeau.
  - `locked_zones(array $provided): array` — sous-ensemble ordonné de `grille::ZONES` : `interacteurs` (tous les interacteurs `locked`), `fonctions` (toutes les FS), `criteres` (tous les critères `locked`), `niveaux` et `flexibilite` (tous les critères `niveauLocked`), `contraintes` (toutes les contraintes) ; une zone vide n'y est jamais ; `ensemble` jamais.
