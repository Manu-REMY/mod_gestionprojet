# v2.12.0 — Volet « Mon avancement » des pages élève Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sur les pages élève des étapes 4 à 9, un volet à droite (sous le formulaire sur écran étroit) réunit statut, note ou paliers, éléments à compléter (liste cliquable mise à jour en direct), dernier retour de l'IA et boutons « Demander un retour » / « Soumettre ».

**Architecture:** Une classe pure `progress` choisit le statut et le retour à afficher. `pages/student_progress_panel.php` rend le volet (html_writer) à partir de `gestionprojet_progress_state()` ; il absorbe les blocs actuels (retour de la note, retour formatif, paliers, bouton Soumettre). Chaque page ouvre un conteneur à deux colonnes après les onglets (`gestionprojet_progress_layout_open()`) et le ferme avec le volet avant le pied de page. Un module AMD `progress_panel` calcule la liste « à compléter » en direct (CDCF via `#cdcfDataField` et des attributs `data-gp-field` posés par `cdcf.js` ; étapes 5–7 via les champs nommés du formulaire et leur `label for`).

**Tech Stack:** Moodle 5.0/5.1 (thème Boost), PHP 8.2, AMD (terser), tests purs, `deploy.sh preprod`.

**Spec:** `docs/superpowers/specs/2026-11-08-volet-avancement-eleve-design.md`.

## Global Constraints

- Version 2.12.0, `$plugin->version = 2026110808`. Pas de changement de schéma.
- Règles inchangées : correction, limite de retours, paliers, verrous, notes (2.11.4).
- Retours toujours filtrés (`answer_leak_filter::student_view`). Daltonisme : symbole + mot. Boutons ≥ 44 px, vrais `<button>` / `<a href>`.
- Pas de CSS/JS inline ; styles préfixés `.path-mod-gestionprojet` ; chaînes en/fr ; DOM par `textContent`.
- Le bouton « Soumettre » garde l'id `submitButton` (lié par `submission.js` et `step6/7/8.js`) ; un seul élément de cet id par page.

## Choix du concepteur

1. Mise en page : grille `minmax(0,1fr) 380px`, volet `position: sticky; top` ; écran < 992 px ou tiroir de blocs Moodle ouvert (`#page.show-drawer-right`) → une colonne, volet sous le formulaire, et ses boutons en barre collante en bas (`position: sticky; bottom: 0`).
2. « Note précédente » quand la copie a une note mais est revenue en brouillon.
3. Liste « à compléter » : étape 4 = cases à compléter vides + pré-remplis inchangés ou contenant « … », « ... », « A compléter » ; sans consigne fournie = énoncés de FS et descriptions de critères vides. Étapes 5–7 = champs `textarea` / `input` texte ou date nommés et étiquetés, encore vides. Étapes 8–9 = pas de liste, lien « Aller au formulaire ».
4. Lecture seule (enseignant qui consulte une copie de groupe ou d'élève, `groupid` passé en paramètre) : pas de « Demander un retour », pas de « Soumettre », pas de boutons de palier.

## Review Focus

1. Copie soumise, IA désactivée, mode paliers, lecture seule enseignant : le volet n'offre que ce qui est permis (test Task 1 / Task 2).
2. Retour formatif plus récent que la note appliquée → le formatif ; sinon le retour de la note (test Task 1).
3. Un seul `#submitButton` par page, et le bouton fonctionne encore sur les six étapes (test Task 3 + navigateur).
4. Champs à compléter : saisie → la liste se met à jour ; clic → défilement + curseur dans le champ (navigateur).
5. Écran étroit et tiroir de blocs ouvert → volet sous le formulaire, rien ne masque un champ (navigateur).

### Task 1: Règles pures `progress` et état serveur

Files: Create `classes/progress.php`; Modify `lib.php`; Test `tests/pure/test_progress.php`.

- `progress::status(int $status, bool $pending): string` → `submitted` | `pending` (soumis et correction en cours) | `draft`.
- `progress::pick_feedback(?object $applied, ?object $formative, ?float $grade, string $teacherfeedback, int $timegraded): array` → `['source' => 'formative'|'applied'|'teacher'|'none', 'evaluation' => ?object, 'text' => string, 'time' => int]` : le formatif l'emporte s'il est plus récent que `applied_at` (ou que `$timegraded` pour une note saisie à la main) ; sinon l'évaluation appliquée ; sinon le commentaire enseignant ; sinon rien.
- `gestionprojet_progress_state(object $gestionprojet, int $step, object $submission, bool $readonly): array` → `status`, `grade` (?float), `previousgrade` (bool), `palier` (état 2.11.2 ou null), `formative` (état 2.11.4 ou null si IA off), `feedback` (résultat de `pick_feedback`, filtré pour l'élève), `cansubmit`, `canask` (bool).
- `gestionprojet_progress_layout_open(): string`.
- [ ] TDD : test RED (statuts, priorités de `pick_feedback` dans les cas formatif plus récent / plus ancien / note manuelle / rien) + statique (`lib.php` définit les deux fonctions, lecture seule coupe `cansubmit` et `canask`) → implement → suite → commit `feat(volet): progress rules and server state`.
