# v2.11.4 — Retour formatif avant soumission (étapes 4 à 9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** L'élève peut demander un retour de l'IA sur sa copie sans la soumettre, jusqu'à N fois par étape (3 par défaut, réglable). La copie reste ouverte ; il voit le dernier retour, filtré ; la soumission finale (la dernière) reste la seule notée. Le bouton « Revenir au brouillon » de l'enseignant est réparé.

**Architecture:** Une évaluation IA marquée `formatif = 1` est mise en file sur un contenu figé (`contenu_json`, comme les paliers), sans application de note ni report au carnet, avec retour toujours filtré. `lib.php` porte l'état et la demande ; un web service `request_formative` ; un bloc élève commun aux étapes (inclus par `student_submit_helper.php`) ; `autosave.js` renvoie la promesse de l'enregistrement pour enregistrer avant la demande.

**Tech Stack:** Moodle 5.0/5.1, PHP 8.2, XMLDB, AMD (terser), tests purs, `deploy.sh preprod`.

**Spec:** demande d'Emmanuel du 8 novembre (réponse au retour sur les « versions ») : retour formatif oui ; pas d'historique à conserver pour l'élève ; la note reste celle de la dernière soumission, copie sur laquelle l'élève continue ; 3 retours par défaut, paramétrable.

## Global Constraints

- Version 2.11.4, `$plugin->version = 2026110807`, étape d'upgrade `2026110807`.
- Champ `gestionprojet.formative_limit` INT(3) défaut 3 (0 = pas de bouton) ; champ `gestionprojet_ai_evaluations.formatif` INT(1) défaut 0.
- Un retour formatif ne verrouille jamais la copie, n'applique jamais de note, ne met jamais à jour le carnet ; retour élève toujours filtré (`answer_leak_filter`).
- Hors retour formatif, comportement inchangé (soumission, note, évaluation affichée à l'enseignant).
- Étape 4 en mode paliers : pas de retour formatif (les paliers jouent ce rôle).
- Chaînes en/fr, pas de CSS/JS inline, daltonisme (mot + symbole).

## Choix du concepteur (à signaler à Emmanuel)

1. Le retour formatif montre le commentaire et les pistes, **sans note** (la note indicative n'a pas été demandée ; elle pousserait à « optimiser » la note).
2. Seul le dernier retour est affiché à l'élève (pas d'historique, décision d'Emmanuel) ; les évaluations restent en base pour l'enseignant.
3. Un retour en échec technique ne compte pas dans la limite.
4. Le retour est refusé si la copie est soumise, si l'échéance est passée, si l'IA est désactivée, ou si un retour est déjà en cours.
5. La page de correction ignore les évaluations formatives (l'évaluation affichée et applicable est celle de la soumission).

## Review Focus

1. Double clic → un seul retour en file, et la limite ne peut pas être dépassée (verrou par copie).
2. Une soumission pendant un retour formatif en cours → la soumission a sa propre évaluation notée (la file ne confond pas les deux).
3. Un retour formatif ne peut jamais être appliqué comme note (`apply_evaluation`).
4. `formative_limit = 0` → aucun bouton, demande refusée côté serveur.
5. Copie individuelle dans un groupe de cours et copie de groupe → le compteur est celui de la copie.
