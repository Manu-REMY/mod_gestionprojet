# v2.11.2 — Validation par paliers FRA / SAT / TS (étape 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** En mode paliers, le groupe fait valider l'étape 4 palier par palier (un bouton par palier de la grille). L'IA juge seulement les parties de ce palier sur un contenu figé au clic ; le serveur décide du verdict selon un seuil en % des points. Un palier validé est enregistré dans `gestionprojet_palier` (lisible par `plan-classe`), ses zones sont figées en entier, et il n'est jamais retiré sauf par le professeur.

**Architecture:** Une classe pure `palier` porte toutes les règles (paliers proposés, parties et zones d'un palier, verdict, gel des zones validées, retrait en cascade). Les fonctions de `lib.php` et deux web services (`request_palier`, `retire_palier`) font les accès base. `ai_evaluator` traite une évaluation de palier : contenu figé, parties du palier seulement, retour toujours filtré, aucun report au carnet de notes. Les pages élève (`step4.php`) et professeur (`grading.php`) affichent l'état des paliers.

**Tech Stack:** Moodle 5.0/5.1, PHP 8.2, XMLDB, web services externes, AMD (minifié avec `npx --yes terser@5.31.0 src/X.js -c -m -o build/X.min.js`, depuis `gestionprojet/amd`), tests PHP purs `php gestionprojet/tests/pure/test_*.php`. Déploiement : `/Volumes/DONNEES/.claude-tmp/gp-deploy/deploy.sh preprod` depuis la racine du dépôt.

**Spec:** `docs/superpowers/specs/2026-11-08-grille-paliers-cdcf-design.md` (sections 4.3, 4.4, 4.6).

## Global Constraints

- Version 2.11.2, `$plugin->version = 2026110805` ; une seule étape d'upgrade `2026110805`.
- Ne pas changer la structure des FS ni le champ `niveau`.
- Mode paliers désactivé (défaut) : comportement identique à 2.11.1 (soumission, note sur 20, carnet).
- Le verdict est calculé côté serveur à partir des points des critères (`score`/`max`), jamais lu dans un texte de l'IA.
- Un palier validé n'est jamais retiré par une tentative suivante ; seul le professeur le retire (et les paliers supérieurs avec).
- En mode paliers : pas de note sur 20, pas de mise à jour du carnet pour l'étape 4, pas d'application de note, retour élève toujours filtré (`answer_leak_filter`), quel que soit `ai_hide_answers`.
- Le plugin n'écrit dans aucune table hors des siennes ; `gestionprojet_palier` : `palier` ∈ `F`, `S`, `TS`, `membres` JSON `[[userid, username], …]`.
- Daltonisme : validé = « ✓ » + mot, non validé = « ⊘ » + mot, en cours = mot ; jamais la teinte seule.
- Chaînes en/fr, commentaires en anglais, GPL, pas de CSS/JS inline, `delete_instance` et privacy à jour pour la nouvelle table.

## Choix du concepteur (à signaler à Emmanuel)

1. Seuil par défaut : 80 % des points du palier, réglable par activité (0 à 100).
2. Ordre des paliers : F, puis S, puis TS ; seuls les paliers présents dans la grille (parties notées) sont proposés ; un palier n'est proposé que si tous les paliers inférieurs présents sont validés.
3. Les zones figées d'un palier = zones de ses parties notées (hors `ensemble`) ; leur contenu de référence = contenu figé de l'évaluation qui l'a validé. Stocké dans `gestionprojet_cdcf.zones_validees` : `{"zone": evaluationid}`.
4. Pendant une évaluation de palier, les zones de ce palier sont aussi figées (contenu figé de l'évaluation en cours) ; le reste de la copie reste modifiable.
5. Gel d'une zone : `interacteurs` = liste entière ; `fonctions` = liste des FS (ids, énoncés, interacteurs ; ni ajout ni suppression), leurs critères restant régis par les autres zones ; `criteres` = liste des critères de chaque FS figée (ids, descriptions) ; `niveaux` = niveaux ; `flexibilite` = flexibilités ; `contraintes` = liste entière.
6. Le retour d'un palier non validé s'affiche à l'élève tout de suite (sans action du professeur), filtré ; un palier validé affiche « ✓ Niveau SAT validé » et le retour.
7. Désactiver le mode paliers rend la main à la soumission classique ; les paliers et zones figées restent en base mais ne s'appliquent plus ; les réactiver les fait revenir.

## Review Focus

1. Double clic ou deux membres du groupe en même temps → une seule évaluation en file pour la copie (test Task 3).
2. L'IA renvoie des critères sans points (`max` 0) ou un JSON invalide → palier non validé, jamais validé par défaut (test Task 1).
3. Une tentative suivante échoue alors que le palier est validé → la ligne reste, les zones restent figées (test Task 1 / Task 3).
4. Requête autosave forgée qui modifie ou ajoute un élément dans une zone validée → rétabli depuis le contenu figé (test Task 1).
5. Mode paliers désactivé → aucune différence avec 2.11.1 : bouton Soumettre, note sur 20, carnet (test Task 3).

**Interfaces — Produces** (namespace `mod_gestionprojet`, classe `palier`, méthodes `public static`) :
- `const ORDER = ['F', 'S', 'TS'];`
- `paliers_in_grid(array $parts): array` — paliers présents parmi les parties notées données (`grille::effective_parts`), dans l'ordre `ORDER`.
- `parts_for(array $parts, string $palier): array` — parties notées de ce palier.

- `freeze(array $student, array $frozen, array $zones): array` — applique le choix 5 ; renvoie la copie sans drapeau.
- `retire_cascade(string $palier, array $validated): array` — `$palier` et les paliers supérieurs présents dans `$validated`.
